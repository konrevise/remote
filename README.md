# konrevise.Remote

дисклеймер: эту программу я писал для личных целей, а не чтобы сделать полноценный продукт, которым кто-то всерьез будет пользоваться.
я хотел изучить базовое устройство веба и кибербезопасности, и так появился этот репозиторий.

## что это такое?
это сервер для сайта.

пользователь на сайте может только управлять состоянием ПК - то есть выключить, перезагрузить, заблокировать или отправить в сонный режим.
зайдите в браузер, вбейте ip-адрес и порт, на котором хостится сайт, и заходите на него.
можно даже полазить в коде да добавить какие-нибудь утилиты.

### аутентификация
для аутентификации в сайт был завезен метод "challenge-response" и хэширование паролей через pbkdf2, а не рискованная дешевая отправка на сервер sha256-хэша пароля.
как зарегистрироваться на сайте? а никак - такого функционала нету в исходниках.
если хотите завезти туда регистрацию, то отправляйте на сервер не только хэш пароля, а соль хэша и количество итераций pbkdf2, чтобы challenge-response адекватно работал. пароль хэшируйте с помощью pbkdf2.

### аутентификационный токен
после успешной аутентификации сервер создает аутентификационный токен, отправляет его клиенту, а сам делает из него хэш, сохраняет хэш токены себе в память и забывает про оригинал, предполагая, что оригинал токена у клиента.
клиент берет оригинал токена и сохраняет его у себя в localStorage до тех пор, пока пользователь не нажмет на "logout", которая стирает токен из localStorage и перенаправляет на страницу логина. (да, xss может стырить токен, но я не использую innerHTML на фронтенде)

### guard
в коде этот механизм назван именно так.
после каждого перехода по страницам клиент спрашивает у сервера инструкции этого механизма, отправляя ему свое текущее место в браузере, а в вообще любом запросе (например, запрос на выключение компьютера-хоста сервера) клиент в заголовках запроса отправляет свой аутентификационный токен. если токен недействителен, то тело запроса на выполнение команды на компьютере-хосте даже не обрабатывается, а guard дает инструкцию клиенту переместиться на страницу логина, а клиент послушно отправляется туда, куда скажет guard.

## запуск
для запуска берите линукс на systemd, .NET 10 и ASP.NET Core.
чтобы сайт работал на вашем линуксе со systemd, то обратите внимание, что некоторые подаваемые на него команды завязаны на xfce (или просто поменяйте команды в исходниках).
запускайте проект через `dotnet run` или соберите его через `dotnet build`, а потом найдите и запустите получившийся исполняемый файл во вложенных директориях в появившейся в директории проекта директории "bin".

## инструкции для правильного запуска сервера
чтобы он не только запустился, а еще и работал, то...

1. **сделайте сертификат** (обязательно в директории проекта потому что нужные файлы берутся именно оттуда) - я в процессе разработки делал самоподписанный сертификат, и все работало, но браузер будет предупреждать о таких сертификатах как об опасности.
**переместитесь в корневую директорию проекта, держите команду для создания сертификата**, если вы не знаете как сделать сертификат или вам нравится бездумно вставлять команды, не думая о последствиях:
```bash
# замените "тыНеПройдешь" на вами желаемый пароль шифрования сертификата - можно что угодно туда ввести, но главное это запомнить пароль.
dotnet dev-certs https -ep ./localhost.pfx -p тыНеПройдешь
```

2. **найдите в исходниках перечисленные файлы**. в исходниках есть константы и свойства, которые заполнены пустышками и отмечены комментариями.
* *addresses.cs* (домен),
* *application.cs* (настройки сертификатов чтобы все на https работало)

3. **сделайте реестр пользователей и отдавайте его программе как** `IEnumerable<User>`.
* *usersService.cs* (нужно прикручивать БД или что-то вроде того - выбор за вами)

4. **настройте sudoers**, чтобы сервис мог управлять питанием без пароля.
краткий гайд: создайте файл в директории /etc/sudoers.d/ и запишите туда правило с помощью команды "visudo" чтобы проверить валидность файла правил.
```text
# замените "N" в начале строки на имя вашего пользователя. если не знаете имя пользователя (что странно), то введите в командную строку "whoami" и вставьте то, что увидели.
N ALL=(root) NOPASSWD: /usr/bin/systemctl poweroff, /usr/bin/systemctl reboot, /usr/bin/systemctl suspend
```
если вам нужно только проверить валидность файла без редактирования, то держите команду, которая делает только проверку такого-то файла:
```bash
# замените "/ваш/файл" на путь к нужному файлу.
sudo visudo -c -f /ваш/файл
```
**а теперь внимание: этот файл нужен только для этого проекта**.
если подробнее, то:
*предупреждение про sudoers:*
	будьте осторожны: если вы (не дай бог...) забудете удалить этот файл, то вы ставите под риск безопасность своих систем!!
	...а еще если вы сделаете хоть какую-то синтаксическую ошибку в файлах правил sudoers, то вы не сможете воспользоваться "sudo" пока не исправите эти ошибки.

*предупреждение про ковыряние в системе:*
	лозунги вроде "свободное ПО" в контексте линукса это не только про свободу распротранения!
	любая ошибка после изменений глубин системы вроде sudoers может привести к поломкам вашей системы, которые исправляются либо отменой ваших изменений, либо переустановкой вашего линукс-дистрибутива.
	лучший антивирус находится между креслом и монитором. кто вооружен - тот должен быть предупрежен.
